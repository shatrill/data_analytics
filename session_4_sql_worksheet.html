DROP TABLE IF EXISTS projects;
DROP TABLE IF EXISTS employees;
DROP TABLE IF EXISTS departments;

CREATE TABLE departments (
    dept_id    INTEGER PRIMARY KEY,
    dept_name  VARCHAR(50) NOT NULL,
    region     VARCHAR(20) NOT NULL
);

CREATE TABLE employees (
    employee_id INTEGER PRIMARY KEY,
    name        VARCHAR(50) NOT NULL,
    dept_id     INTEGER REFERENCES departments(dept_id),   -- may be NULL (not yet assigned)
    salary      INTEGER NOT NULL
);

CREATE TABLE projects (
    project_id   INTEGER PRIMARY KEY,
    employee_id  INTEGER REFERENCES employees(employee_id), -- may be NULL (not yet staffed)
    project_name VARCHAR(60) NOT NULL,
    hours_logged INTEGER NOT NULL
);

Part B: Guided Example: Build a Department Scorecard

Type (don't paste!) each query and run it. Compare your output to the expected result.

Step 1: INNER JOIN, matches only

Connect each employee to their department. INNER JOIN keeps a row only when the key exists in both tables. Aliases (e, d) keep things short.

SELECT e.name, d.dept_name, e.salary
FROM employees e
INNER JOIN departments d ON e.dept_id = d.dept_id
ORDER BY d.dept_name, e.name;

Count the rows: 11. We have 12 employees. Who disappeared, and why?

Step 2: LEFT JOIN, keep everyone on the left

Change one word. LEFT JOIN keeps every row from the left table (employees), even without a match. Missing right-side values become NULL.

SELECT e.name, d.dept_name, e.salary
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.dept_id
ORDER BY d.dept_name, e.name;

12 rows. Jonas Lindqvist is back, with a NULL department because he has not been assigned one yet. An INNER JOIN would silently drop him from a payroll report!

Engine note: PostgreSQL sorts NULLs last, SQLite sorts them first, so Jonas may appear at the top or bottom of your result.

Step 3: COALESCE, replace NULL with something readable

COALESCE(value, fallback) returns the first non-NULL value. Executives should see Unassigned, not a blank cell.

SELECT e.name,
       COALESCE(d.dept_name, 'Unassigned') AS department,
       e.salary
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.dept_id
ORDER BY department, e.name;

Step 4: CASE WHEN, create salary tiers

CASE WHEN works like an IF/THEN ladder. It checks conditions top to bottom and stops at the first true one, so put the highest threshold first.

SELECT e.name,
       COALESCE(d.dept_name, 'Unassigned') AS department,
       e.salary,
       CASE
           WHEN e.salary >= 90000 THEN 'Senior'
           WHEN e.salary >= 65000 THEN 'Mid'
           ELSE 'Associate'
       END AS salary_tier
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.dept_id
ORDER BY e.salary DESC;

Step 5: The scorecard, GROUP BY + CASE inside an aggregate

Now roll everything up to one row per department. A neat trick: SUM(CASE WHEN ... THEN 1 ELSE 0 END) counts only the rows that meet a condition.

SELECT COALESCE(d.dept_name, 'Unassigned')                  AS department,
       COUNT(*)                                             AS headcount,
       ROUND(AVG(e.salary), 0)                              AS avg_salary,
       SUM(CASE WHEN e.salary >= 90000 THEN 1 ELSE 0 END)   AS senior_staff
FROM employees e
LEFT JOIN departments d ON e.dept_id = d.dept_id
GROUP BY COALESCE(d.dept_name, 'Unassigned')
ORDER BY avg_salary DESC;

Expected result:

department headcount avg_salary senior_staff
Engineering 3 97000 2
Finance 2 81000 0
Unassigned 1 70000 0
Marketing 3 64000 0
Sales 3 58000 0

🎉 You just built an executive-ready department scorecard by combining a LEFT JOIN, COALESCE, CASE WHEN and GROUP BY.
